# 反復拡張とエポック数を増やすことの違い

作成日：2026年10月23日

対象：capsuleの元画像・反復・edge回転拡張の比較実験

## 1. 最初に押さえる結論

**どちらも、同じ訓練画像を使う回数を増やす方法です。反復するだけでは、新しい画像の情報は増えません。**

ただし、今回のコードでは「同じ画像を10回並べて100エポック学習すること」と「元画像のまま1,000エポック学習すること」は完全には一致しません。違うのは、主に次の3点です。

- 端数バッチができる回数と、それに伴うモデルの更新回数。
- シャッフルで作られるバッチの組み合わせ。
- エポックに合わせて変えるβの、更新回数に対する進み方。

この資料の数値は、コードとデータ枚数から計算した値です。**元画像で1,000エポック学習する新しい実験を実施した結果ではありません。**

## 2. エポック・バッチ・更新とは何か

### エポック：用意した訓練サンプルを一巡する単位

元画像219枚を使う場合、219枚を一巡すると1エポックです。

同じ画像を10回ずつ使うようにすると、学習プログラムが扱うサンプル数は延べ2,190枚になります。この2,190サンプルを一巡して1エポックです。元になった画像は219枚のままです。

つまり、**反復前後では「1エポックで使う画像の延べ枚数」自体が違います。**

### バッチ：まとめてモデルに渡す画像の組

今回はバッチサイズ32なので、原則として32枚ずつモデルに渡します。

### 更新：誤差を使ってモデルの重みを変える処理

今回のコードでは、1バッチごとに誤差と勾配を求め、`optimizer.step()` を1回実行します。したがって、更新回数はバッチ数と同じです。

```text
訓練画像を一巡する                    ＝ 1エポック
その中で、原則32枚ずつまとめる         ＝ バッチを作る
1バッチから誤差・勾配を計算して重みを変える ＝ 1回の更新
```

1枚を見せるたびに1回更新する設定ではありません。

## 3. 219枚を使った具体的な比較

### なぜ、画像数が10倍でも更新回数はぴったり10倍にならないのか

現在は `drop_last=False` なので、最後の32枚に満たない画像も1バッチとして使います。

```text
元画像219枚：
[32枚] [32枚] [32枚] [32枚] [32枚] [32枚] [27枚]
                                                   合計7バッチ

10回反復した2,190枚：
[32枚] × 68バッチ ＋ [14枚]
                      合計69バッチ
```

219 ÷ 32 は6余り27なので、端数を含めて7回更新します。
2,190 ÷ 32 は68余り14なので、端数を含めて69回更新します。

| 項目 | 元画像のみ×100エポック | 10回反復×100エポック | 元画像のみ×1,000エポック |
|---|---:|---:|---:|
| 元となる画像数 | 219枚 | 219枚 | 219枚 |
| 1エポックの延べ枚数 | 219枚 | 2,190枚 | 219枚 |
| 全体で各元画像を使う回数 | 100回 | 1,000回 | 1,000回 |
| 全体の延べ使用枚数 | 21,900枚 | 219,000枚 | 219,000枚 |
| 1エポックの更新回数 | 7回 | 69回 | 7回 |
| 全体の更新回数 | 700回 | 6,900回 | 7,000回 |

**10回反復×100エポックと、元画像×1,000エポックは、延べ使用枚数が同じでも、更新回数は100回違います。**

一般に、現在のように最後の端数も使う場合は、次の計算になります。

```text
1エポックの更新回数 ＝ 訓練サンプル数 ÷ バッチサイズを切り上げた値
全体の更新回数     ＝ 1エポックの更新回数 × エポック数
```

枚数がバッチサイズで割り切れる場合、この端数による違いはなくなります。例えば元画像320枚・バッチ32なら、通常は10更新、10回反復では100更新で、ちょうど10倍です。ただし、後述のシャッフルやβの違いは別に残ります。

## 4. 更新回数以外にも違いがある

### 4.1 シャッフルと、同じバッチ内の画像の重複

現在は `shuffle=True` です。

元画像のみでは、1エポックの中で元画像を1回ずつ使い切ります。一方、10回反復では、同じ元画像に対応するサンプル番号が10個あります。その2,190個の番号を混ぜるため、**同じ元画像が同じバッチに複数入る場合があります。**

4枚の画像A・B・C・Dとバッチサイズ2で、2回ずつ使う簡単な例を考えます。

```text
元画像を2エポック使う例：
  1エポック目：[A, B] [C, D]
  2エポック目：[A, C] [B, D]

2回反復した8サンプルを1エポック使う例：
  [A, A] [B, C] [B, D] [C, D]
```

これは起こり得る並びの一例です。どちらも各画像を2回使っていますが、1回の更新で組み合わせる画像が違います。

今回のHybridモデルはBatchNormも使います。BatchNormは学習中のバッチ内の統計量を使うので、バッチの組み合わせは学習に関わります。「使った画像と延べ回数が同じ」というだけでは、同じ学習結果になるとは限りません。

### 4.2 βを増やす速さが、更新回数に対して異なる

今回のVAEでは、画像を復元する誤差に加え、潜在変数の分布に制約をかけるKL項を使います。βは、このKL項に掛ける係数です。

現在のコードは、各エポックの開始時に次の値を設定します。

```python
beta = min(1.0, epoch / 50)
```

`epoch` は0から始まるので、1エポック目はβ=0、50エポック目はβ=0.98、**51エポック目からβ=1**です。そのエポックの途中ではβを変えません。

| βが初めて1になるまでの経過 | 10回反復×100エポック | 元画像のみ×1,000エポック |
|---|---:|---:|
| それまでに完了したエポック | 50 | 50 |
| それまでに使った延べ枚数 | 109,500枚 | 10,950枚 |
| それまでの更新回数 | 3,450回 | 350回 |
| β=1で行う最初の更新 | 3,451回目 | 351回目 |

つまり反復条件は、**βが小さい段階で、より多くの画像と更新を経験します。**

そのため、現在の設定のままでは、反復条件とエポック数を増やす条件の差を「更新回数だけの違い」とは説明できません。

なお、この表の元画像のみの条件は、100エポックでも1,000エポックでも、最初の50エポックまでの進み方は同じです。

### 4.3 VAEのサンプリングにも注意する

画像を反復しても入力の画素値は同じですが、今回の学習は潜在変数をランダムにサンプリングします。そのため、同じ画像を再び使ったときも、内部の潜在変数や復元結果が毎回完全に同じとは限りません。

これは元画像を多くのエポックで使う場合にも共通です。「画像の反復で新情報が増える」という意味ではありません。学習過程を完全に一致させたい場合には、画像の順番だけでなく乱数の使われ方も揃える必要があります。

## 5. どの条件を揃えると、同じ／近い学習になるか

「エポック数」という名前だけで比較せず、実際の学習の進み方を見ます。

| 揃える対象 | 確認すること |
|---|---|
| 画像の処理 | 同じ前処理済み画像を使い、反復のたびに別のランダム加工をしない |
| 使う量と更新 | 延べ使用枚数、更新回数、バッチサイズ、端数バッチの扱い |
| 更新ごとの入力 | バッチ内の画像とその順序 |
| 学習の開始状態 | 初期重み、BatchNormの状態、Adamなど最適化手法の内部状態 |
| 係数のスケジュール | βや学習率を、同じ更新時点で同じ値にする |
| ランダム性と計算環境 | サンプリングの乱数、処理順、計算の再現性 |

各更新で同じバッチ・同じ係数・同じ乱数と状態を使うなら、エポックをどこで区切るかという呼び方自体は、重みの更新を変えません。ただし、エポックの境界で係数変更や追加処理を行う実装では、その処理も揃える必要があります。

実務上、学習量を比較しやすくする方法の一つは、βや学習率をエポック数ではなく**累積更新回数**に対応させることです。ただし、更新回数を揃えるだけでバッチの組み合わせまで一致するわけではありません。

これは今後比較条件を決める際の考え方です。**今回作成済みのノートブックの学習条件を、この資料に合わせて変更したわけではありません。**

## 6. 今回のA・B・C比較で、反復条件を設ける理由

今回の目的は、反復という加工で新しい画像情報を作ることではありません。

**「画像を何度も使って学習量を増やすこと」と「向きを変えた入力を与えること」を分けて調べるための比較対象として、Bを置いています。**

| 比較 | 揃っている主な条件 | 調べること・解釈の範囲 |
|---|---|---|
| A：元画像 vs B：反復 | 元画像と前処理 | 新情報を加えず繰り返す学習の影響。ただし更新量・βの進み方・バッチ構成も変わる |
| B：反復 vs C：回転 | 延べ枚数、更新回数、元画像の対応、入力番号の順、β、初期重み | 回転・edge補完・再サンプリングを含む入力変更の影響 |
| A：元画像 vs C：回転 | 元の訓練画像、モデルなど | 学習量と入力変化を合わせた影響。回転だけの効果とは言えない |

B/Cでは同じ元画像・サンプル番号が同じ更新位置に来るようにしています。ただし、Cは回転・edge補完で画素値が変わるため、その後の重みや復元が同じになるように揃えるものではありません。

また、Cの結果が変わっても、それを「向きの多様化だけ」の効果とは断定できません。補完された背景や、回転・縮小による画素の変化も含まれるためです。

- 反復や回転で独立な元画像を2,190枚集めたわけではありません。元画像は219枚です。
- Bが良くなったとしても、それだけで「訓練データの情報が増えたから」とは言えません。
- B/Cの差は、今回のモデル・前処理・学習条件・データでの結果として解釈します。
- 異常検知性能は共通テストのAUROCで比較します。正常画像の復元誤差だけで判断しません。

## 7. 教授への説明に使える短い要約

> 反復は、元画像の情報を増やさず、同じ画像を学習に使う回数を増やす方法です。エポック数を増やすことと本質的には近いですが、今回は端数バッチ、シャッフル、βを増やすタイミングに違いがあります。反復条件と回転条件では延べ枚数・更新回数・βなどを揃え、回転と背景補完を含む入力変更の影響を比較します。
